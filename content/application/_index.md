申请准备不是把材料凑齐后等待结果。先明确目标，再把课程与项目积累整理成可核对的材料，通过练习发现问题，最后按具体通知管理报名与确认。

米醋的准备方法围绕三件可交付的事展开：**能解释的专业知识、有依据的项目经历、查得清的申请记录**。可以从当前最影响下一步的一件事开始。

## 按当前任务开始

| 你正在处理的事 | 建议先读 | 可以完成的产出 |
| --- | --- | --- |
| 不知道怎样比较目标 | [院校与方向选择]({{< relref "application/choosing.md" >}}) | 明确选择条件，完成一次方向小体验 |
| 要准备本次投递 | [申请材料与文书]({{< relref "application/materials.md" >}}) | 整理事实库，对齐简历、陈述和展示材料 |
| 想联系导师 | [联系导师]({{< relref "application/mentors.md" >}}) | 完成研究匹配卡，提出一个具体问题 |
| 项目做过但讲不清 | [竞赛与项目整理]({{< relref "application/projects.md" >}}) | 建立证据线，完成一页调试复盘 |
| 报名和通知容易遗漏 | [夏令营与预推免]({{< relref "application/camps.md" >}}) | 分别检查申请前、提交后和参加前状态 |
| 即将参加面试 | [面试准备]({{< relref "application/interviews.md" >}}) | 练一段90秒介绍，完成一次有记录的模拟 |
| 基础知识理解不牢 | [专业课、数学与方向复习]({{< relref "application/review-basics.md" >}}) | 一张知识卡、一段闭卷解释、一项小验证 |
| 要参加编程或项目考核 | [机试与短期项目考核]({{< relref "application/coding-assessments.md" >}}) | 依据错误复练，从干净目录检查交付物 |
| 准备确认接收结果 | [正式推免与后续事项]({{< relref "application/confirmation.md" >}}) | 核对对象、系统状态和后续要求 |

## 让一项任务带动下一项

项目复盘暴露出概念问题，就回到课程做知识卡；材料里的一句话找不到依据，就先核对记录；模拟中答非所问，就改表达再练一次。不必同时新增项目、扩写材料和刷大量题目，先解决已经发现的具体缺口。

这些方法适用于电子、嵌入式、自动化和计算机等方向的准备，具体任务按自己的经历和目标调整。方法中的练习时长、产出格式和自问问题均是建议，不是统一考纲或院校规定。

资格、材料条件、考核形式和操作期限以对应年度的官方通知为准。尚未查明的信息保留为待确认，不用他人的录取结果推断自己的机会。
