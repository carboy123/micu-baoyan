先画清复习范围，再练习把概念用于解释问题。对电子、嵌入式、自动化和计算机学员，我们建议把 **课程知识、自己做过的项目、目标方向要求** 放在同一张表中，找到它们的交点，而不是把所有可能出现的名词都放进计划。

下面是学习方法与任务示例，不是统一考纲。公开考核范围、指定参考书和具体形式优先按目标院系通知安排。

## 用三列确定优先级 {#scope}

| 要复习的主题 | 为什么现在需要它 | 怎样检查是否理解 |
| --- | --- | --- |
| 通知明确要求的基础 | 对应实际考核范围 | 按要求练习解释、推导或求解 |
| 简历和项目中出现的技术 | 需要为自己写出的经历负责 | 解释使用条件、实现位置与验证方式 |
| 与申请方向相关的欠缺 | 影响理解目标研究内容 | 找到一个能完成的小问题并尝试解决 |

先处理已有明确要求、又确实薄弱的主题。某个知识点只是在群聊里频繁出现，并不自动成为当前最优先的任务。

## 一张知识卡，完成四个动作 {#knowledge-card}

选一个概念，关闭资料后完成下面四步：

1. **用自己的话解释。** 说明它解决什么问题，与相近概念怎样区分。
2. **写出条件。** 公式、方法或结论在什么前提下适用，符号或接口分别代表什么。
3. **做一个小例子。** 可以是手算、画流程、写最小程序或使用已有实验条件验证；例子应小到能追踪每一步。
4. **换一个条件再解释。** 输入、约束或假设变化后，哪些结论仍成立，哪些需要重新检查。

一张卡只处理一个具体问题。卡背面记录教材页码、课程位置或所用器件和软件版本对应的官方资料，避免记住了流畅但错误的解释。

## 四个方向可以怎样开始

以下是选择任务的例子，按自己的课程和项目取舍；完成它们不代表完成整门课程复习。

| 方向 | 可以选择的小任务 | 交付物 |
| --- | --- | --- |
| 电子与硬件 | 选一个做过的电路模块，写清输入、输出和约束，再对照自己的分析、仿真或测量 | 一张模块图、一组有条件说明的结果 |
| 嵌入式 | 追踪一个数据从外设到程序输出的过程，标出接口、缓冲与处理位置 | 一张数据路径图、一个可复现的小程序或日志 |
| 自动化 | 针对熟悉的对象写清模型假设，说明测量、控制与执行如何衔接 | 一张闭环图、一次改变工况的分析记录 |
| 计算机 | 选一种实际用过的数据结构或机制，用小输入走完一次操作 | 操作过程、复杂度分析或最小验证程序 |

这些任务用于发现“哪里解释不清”。有缺口时，回到相应课程补基础，再更新知识卡，避免只把项目现象背成固定答案。

## 计算机基础怎样串起来

数据结构与算法可围绕表示、操作、复杂度和适用场景检查；操作系统可从一个程序的执行过程理解进程、同步、内存和输入输出；网络可追踪一次请求以及可能失败的环节；组成与体系结构可联系指令、数据表示和存储访问。

所用语言中的类型、内存或运行机制，也可以用最小程序验证。选择自己能明确提出问题的主题，写出预期结果后再运行，比只阅读代码更容易发现理解上的偏差。

“408”常被用作范围简称，不能据此认定保研考核必然采用相同课程组合、权重或题型。

## 数学：从公式回到对象和条件

复习时把“会套公式”拆成三个检查点：识别数学对象、说明适用前提、解释结果的意义。

| 主题 | 可采用的自检动作 |
| --- | --- |
| 微积分 | 给每个符号说明含义，用小例子检验计算，并解释它描述的变化或累积 |
| 线性代数 | 写清向量和矩阵的维度，连接代数运算与自己理解的空间或数据关系 |
| 概率与统计 | 说明随机对象、已知条件与假设，区分计算结果和对问题的解释 |
| 离散数学 | 把自然语言条件转成清楚的逻辑、关系或图，再核对推理是否覆盖条件 |
| 最优化 | 写清目标、变量和约束，解释为什么求解这个目标，以及结果如何检验 |

不要只记结论名称。一个条件换掉后不能直接沿用的地方，正好可以成为下一张知识卡。

## 机器学习与视觉方向：先说清一次实验

如果申请方向或自己的项目涉及机器学习，不必先背一整串模型名。先把一个熟悉任务的输入、输出、数据划分、训练目标、评价指标和运行条件连起来。

随后围绕实际采用的方法补课：用到哪种结构，为什么选它；优化方法做什么；有哪些比较对象；错误样本集中在哪里。CNN、Transformer、归一化等内容按自己的项目和目标需求展开，未用过的模型不包装成实践经验。

比较结果时检查实验条件是否一致。改动一个因素后再比较，才能更清楚地解释差异；已有记录无法支持的因果结论，不写成已经证明的事实。

## 每周用产出来复测 {#weekly-output}

一周可选少量重点，留下三种可回看的结果：**一张知识卡、一段闭卷解释、一项小验证**。数量按课程负担调整，重点是发现并解决了什么问题。

复测时不要原样背上一轮答案。换一个小输入，或请同伴改变一个条件，检查自己能否继续推理。将错误分为概念、条件、计算、实现和表达，下一轮只给明确的薄弱点安排任务。
