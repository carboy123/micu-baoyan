联系导师前，先明确自己想得到什么信息：了解研究方向、询问正式申请渠道，还是确认已有通知中的具体安排。一次沟通能解决一个清楚的问题，比堆满自我评价更有帮助。

是否需要提前联系、何时双选以及导师在选拔中的职责，按具体院系规定理解。积极回复不能替代本校资格、院系审核和正式系统手续。

## 先做一张研究匹配卡 {#matching-card}

从导师或团队官方页面开始，选一个公开的研究问题或工作介绍，写下四项内容：

| 项目 | 要写什么 |
| --- | --- |
| 我实际读到了什么 | 具体页面、论文或介绍的名称，以及自己理解的问题 |
| 我已有的联系 | 与该问题相关的课程或亲自完成的项目工作 |
| 我还不理解什么 | 一个具体技术环节或培养安排，不假装已经读懂 |
| 本次想确认什么 | 对方能够回答、且确实影响下一步的问题 |

例如，做过嵌入式或机器人项目的学员，可以从自己遇到的感知、计算、控制或系统实现问题出发找联系，而不是只因为双方简介中都有“人工智能”就认定研究匹配。

这张卡是沟通准备，不是需要发给导师的固定附件。读过多少文章也不是目的，能准确说明自己理解和不理解的边界更重要。

## 用五个信息块写初次邮件

1. **身份与用途**：真实在读身份、申请入学年度与类型。
2. **联系原因**：实际阅读的研究内容，以及想交流的问题。
3. **相关经历**：一项能展开说明的本人工作。
4. **明确请求**：询问方向、申请渠道或是否方便进一步交流。
5. **必要附件**：只说明实际附上的材料，让文件容易识别和打开。

写完后尝试删去泛泛的赞美和重复介绍。如果删除后联系原因反而更清楚，就保留简洁版。用自己的话写，不把同一封邮件只替换称谓后直接群发。

[联系导师邮件框架]({{< relref "resources/mentor-email.md" >}})可用于检查信息是否完整，内容仍应按实际情况重写。

## 发送前，检查对方最容易遇到的障碍

确认官方公布的邮箱、姓名、单位、申请年份和附件都正确。检查正文是否能直接看出问题，附件是否需要额外申请访问权限，文件名是否清楚。

如果学院已经说明统一报名或不接受某种提前联系，应按该安排处理。不要为了追求“联系过”而绕过现有流程。

## 进一步交流时，带着可展示的一个问题

如果获邀交流，准备一段简短介绍和一个能展开的项目片段。可以带一张系统图、一条调试记录或一组结果，说明问题、本人工作、验证和局限。

自己的提问也可以更具体：团队目前关注什么问题，新生通常需要怎样的基础，自己不清楚的培养安排应在哪里查。招生程序和名额等事项以正式渠道能够确认的信息为准，不根据措辞自行推断承诺。

## 记录事实，再决定怎样跟进

把沟通分成“对方原话或明确安排”“自己理解”“仍需确认”三列。这样下一次联系时能回到具体事项，不会把“欢迎报名”逐渐记成“保证接收”。

没有回复不足以判断原因。跟进前先看是否已有处理时间、正式通知是否更新、自己是否有需要补充的新信息；不要按固定间隔反复发送同样内容。

收到不同回复后，可以这样安排：

| 实际回复 | 下一步 |
| --- | --- |
| 提供正式报名入口 | 阅读通知并按要求申请，沟通和报名分别记录 |
| 要求补充材料 | 核对内容、提交对象与期限，按要求提供 |
| 邀请进一步交流 | 确认形式与时间，准备真实经历和问题 |
| 表达积极意向 | 询问与院系程序怎样衔接，不自行跳过手续 |
| 明确无相关安排 | 更新目标记录，按自己的计划继续准备其他项目 |

自己的安排改变时，按相应规则及时更新对方需要知道的信息。正式状态仍须回到 [推免与后续事项]({{< relref "application/confirmation.md" >}}) 中分别核对。
