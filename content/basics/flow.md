保研流程可以分成 **本校推荐、院校申请与考核、全国系统确认、后续审核与入学**。前两部分在时间上可能交叉，准备时需要分别跟进，不能只盯着其中一条线。

本文讲环节和任务，不把往年的月份或某一所学校的安排当作统一日历。当年国家节点见 [2027 入学年度推免安排]({{< relref "application/calendar-2027.md" >}})，具体院系事项还需阅读该项目通知。

## 先了解两条并行的线

| 本校推荐线 | 目标院校接收线 |
| --- | --- |
| 查清适用办法、成绩与成果口径 | 明确研究方向，建立目标项目表 |
| 按当年要求申报，提交真实材料 | 查条件、准备投递版本，按通知报名 |
| 跟进评价、公示与后续手续 | 获邀后确认参加，完成规定考核 |
| 核对推荐资格状态 | 读清阶段结果，跟进双选、补材料等事项 |

积极的院校或导师反馈不会自动产生本校资格；获得本校推荐也不会自动产生目标院校接收结果。两边的状态分别记录，后续按官方要求完成全国系统中的正式操作。

## 从准备到确认，逐环节检查

| 环节 | 当前要做什么 | 完成的标志 |
| --- | --- | --- |
| 了解条件 | 找到本校规则，查目标项目条件，确认各自适用对象 | 能指出判断条件所依据的正式文件 |
| 集中报名前 | 整理目标项目、材料母版和证明文件 | 每个目标都有信息记录，材料缺项明确 |
| 报名开放后 | 逐项对照通知准备本次投递版本并提交 | 已检查系统回显或回执，记下后续要求 |
| 获邀考核后 | 确认是否参加，安排时间地点，准备对应考核 | 已完成所需确认并知道参加方式 |
| 收到阶段结果后 | 读清结果效力、条件与期限 | 当前状态和下一步都能对应通知原文 |
| 全国系统阶段 | 按当年规定处理志愿、复试与待录取等通知 | 已核对自己需要操作的事项和系统状态 |
| 确认去向后 | 跟进资格复核、本科学业和入学通知 | 后续材料与任务有清单、来源和完成记录 |

报名系统中的“保存”是否等于“提交”、提交后能否修改、是否还要回复邮件等，都需要在当前通知与系统界面确认。不要仅凭上传过附件就认定报名已经完成。

## 如何理解夏令营、预推免与后期机会

夏令营、预推免可能是院系安排申请、交流或考核的不同形式。它们之间是否互认结果、是否需要重新报名、是否限制已参加或未参加的学生，由相应通知决定。

后期补招和递补也需要满足项目条件并完成正式流程。遇到群聊中的“九推”“十推”“捡漏”等称呼，先寻找官方通知，确认是否真的有公开申请入口，再判断自己是否符合条件。

不能用某位学长学姐经历的顺序，推断所有院系都有相同批次、考核方式或后续机会。

## 每收到一次结果，都问这四个问题

1. **谁发出的？** 本校、目标学院、导师个人，还是正式系统？
2. **对应什么项目？** 院系、专业、培养类型、专项与批次是否明确？
3. **结果的效力是什么？** 获邀考核、优营、候补、意向，还是系统中的正式通知？
4. **接下来做什么？** 是否需要补材料、双选、考核、回复或确认，期限是什么？

将这些信息保存到 [申请台账]({{< relref "resources/application-ledger.md" >}})。如果说明不清，向该项目公布的负责渠道询问，并保留回复；不要自行把不同名称合并成“已上岸”。

## 全国系统不是可省略的步骤

国家推免服务系统承担资格、报考、录取与备案公开等正式工作。研招网说明，推免生需要通过系统填写志愿、接收并确认相关通知，最终名单以系统备案信息为准。

具体操作时间、志愿和通知的处理规则，应按对应入学年度的系统说明及招生单位要求核对。不要只等学校联系，也不要把“928”“925”等历史俗称当作当年的操作日历。

进入需要作出正式确认的环节前，可用 [结果确认检查单]({{< relref "resources/result-checklist.md" >}}) 核对项目条件和遗漏事项，具体手续见 [正式推免与后续事项]({{< relref "application/confirmation.md" >}})。

## 记录日期时，至少区分四类信息

| 字段 | 记录内容 |
| --- | --- |
| 申请年份 | 实际报名、参加申请的公历年份 |
| 入学年度／届次 | 通知明确写出的研究生入学年份或届次 |
| 通知发布日期 | 文件或网页实际发布的日期 |
| 具体事项期限 | 对应材料、回复、考核或确认的日期和时刻 |

同一个项目可能有多个截止事项。国家系统窗口不替代院系的材料截止或回复期限，后者可能更早。未知年份或日期写“待确认”，不要根据标题中的一个数字推断其余字段。
