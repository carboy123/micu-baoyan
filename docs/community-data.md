## 年份与统计口径

用户于 2026-10-03 确认成果统一按毕业届别展示为“2026 届”和“2027 届”。原名 2025 去向表对应本科 2022 级、2025 年保研申请、2026 届；申请年份仍单独保留为 2025。2027 届未单独提供申请年份，不推算填入。

2026 届的统计分组为 `cohort-2026`，旧 `application-2025` 成果链接兼容跳转到该组。感言标题、届别与筛选入口同步更新；为保留已公开链接和记录身份，文章路径及 recordId 中的 `2025` 不改。旧面经原文中的届次不受此次成果分组修正影响。

本科层次与最终去向层次按原问卷单选项统计，不根据学校名重新分类。每个维度包含未知项，合计必须等于该批样本数。比例保留一位小数，可能有四舍五入差异。院校分布使用最终去向，不用 offer 数量代替最终去向人数；无法明确院校的条目单列，不从分母删除。数据描述已收集样本，不是全体学员成功率，也不用于推断培训的因果效果。

## 一处维护去向

成果页统一读取 `layouts/_partials/site/outcomes-data.html`：

- `data/outcomes.json` 保存批次标识、年份口径、原始记录数、整理说明及导入时汇总。
- `profileBased: true` 的 2027 届从已发布的 `type: student` 档案计算，忽略导入快照的计数；因此修改档案的 `school`、`undergraduateTier`、`destinationTier` 会同时更新个人页与比例图。
- 2026 届的去向统计保留匿名汇总，50 篇感言独立展示，不用于反推身份或增加成果人数。后续只有核实为新增样本的档案才能追加计数，原样本认领不能重复增加。
- `countInOutcomes: true` 必须由维护者审核，并关联有效 `periodId`。新模板默认为 `false`。草稿、未发布档案不计入。
- 为新毕业届别增加一个 `profileBased: true` 的批次元数据，再允许对应学员档案计入。不要直接在 HTML 中修改数字。

`rawRecords` 和导入快照描述历史原始问卷；后续新投稿增加时，应同步维护本期资料范围说明，不能把新投稿称为原始问卷回收数。

## 内容补充与认领

学员档案路径为 `content/students/<studentId>/index.md`。展示名默认匿名编号，本人确认后可改成昵称；实名、头像、成绩等均自愿公开。`featured` 由工作室在内容完善后另行推荐，本次没有自动评选。

面经放在 `content/experiences/`，一场独立经历一篇。稳定 `recordId` 用于校验，`studentId` 只有核对作者后才填写。个人页会自动列出关联面经，面经详情会链接到个人页。原始未知信息保持空值，问卷“跳过”不等于没有该考核环节。

2026 届匿名感言同样放在 `content/experiences/`，内容类型为“上岸感言”，每篇保留独立 `recordId`，`studentId` 留空。只有后续核对作者且确认本人同意关联，才建立与学员档案的对应关系；不能凭文字或去向相似自动认领。

投稿者按 [CONTRIBUTING.md](../CONTRIBUTING.md) 操作。PR 的自动检查只检查格式与一致性，真实性、公开范围及身份认领由工作室审阅。合并到主分支后才触发发布，公开 PR 在合并前已经可见。

## 导入器与检查

导入器只使用 Python 标准库，不修改 Excel 或 Markdown 原件。通常只运行默认检查：

```powershell
python scripts/import-studio-data.py
python scripts/check-contributions.py
python -m unittest discover -s tests -p "test_contributions.py"
node --test tests/core.test.cjs tests/students.test.cjs tests/outcomes.test.cjs
python tests/outcome-aggregation.py --hugo tools/hugo/hugo.exe
```

首次写入参数为 `--write`。已有公开文件与导入输出不同时，导入器会拒绝覆盖；`--replace-existing` 仅用于明确需要从原稿重新生成的受控整理，不应覆盖学员后续补充。原始文件不随公开仓库分发，缺少原稿的 CI 不运行导入器。

生产构建及子路径检查使用 README 中的现有命令。`site-check.py` 验证各比例分布的合计、真实面经编号、学员关联路径、草稿隔离、内链、资源与本地原件哈希。投稿工作流只读，不部署；主分支发布前重复执行相同校验。
